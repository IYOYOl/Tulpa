# 提示词流水线（Prompt Pipeline）

一次拍照从「按下快门」到「拿到成片」，中间经过的模型调用、参数与裁切都在这里说明。
对应源码：

- `app/src/main/java/com/lxylx/aicamera/AppViewModel.kt` —— `onCaptured` / `processOneInner`（队列 + 流程编排）
- `app/src/main/java/com/lxylx/aicamera/net/ApiClient.kt` —— 三个阶段的提示词、多图请求、生图参数
- `app/src/main/java/com/lxylx/aicamera/util/Aspect.kt` —— 比例 → 生图 `size`

---

## 总览

```
拍照
 └─ 裁切到所选比例 → 场景照（JPEG，长边 ≤1536 上传用）
     ├─ ① DeepSeek：视觉分析员           （场景图 + 参考人物图）
     ├─ ② DeepSeek：摄影师 / 灯光师 / 合成师 三方商讨（复用上一步分析）
     ├─ ③ DeepSeek：导演定稿             （输出最终 prompt）
     └─ ④ 火山方舟 Seedream 生图          （场景图 + 参考人物图 + prompt + size）
          └─ 结果按目标比例本地裁切 → 存 App 内部 + 自动写入系统相册
```

每张照片 = **3 次 DeepSeek 调用 + 1 次方舟生图**，串行执行。

---

## 阶段 ①：视觉分析员

输入：场景图（必要时也带参考人物图）
目标：**详细**拆解场景，供后面三方讨论

输出 JSON：

```json
{
  "space": "空间结构：前景/中景/远景、地面材质、墙面、透视线",
  "camera": "拍摄高度、焦距感、画面是否倾斜",
  "light": "主光方向、软硬、色温、明暗对比、反光面、阴影方向",
  "objectOrder": "主要物体的朝向与排列规律",
  "anchors": [{ "where": "可交互点", "contact": "接触面" }],
  "risks": ["最容易露馅的地方", "..."]
}
```

---

## 阶段 ②：三方商讨

输入：阶段 ① 的分析结果
目标：三个人从不同角度给意见，**不要统一结论**（交给导演拍板）

输出 JSON：

```json
{
  "photographer": "位置、占画面比例、朝向、镜头一致性、遮挡关系",
  "lighting": "受光、阴影与投影方向、色温、接触阴影、地面反射",
  "compositor": "最容易露馅的点 + 规避办法（比例、接触点、边缘、材质、画质）"
}
```

---

## 阶段 ③：导演定稿

输入：分析 + 三方意见 + 用户设置
目标：产出可直接执行的生图提示词

硬性约束（写在系统指令里）：

- 人物写实程度由 `二次元 / 三次元` 开关决定
- 人物状态由 `镜头感` 开关决定
- 顺着场景透视与物体朝向安排互动，不为了配合人物改变场景
- 参考图只提供身份特征（长相、发型发色、服装、体型）
- 不改变原照片内容与构图，不添加原图没有的元素，不加文字水印
- 长度 ≤ 300 字

输出 JSON：

```json
{
  "interaction": "与场景里哪个物体怎么互动",
  "place": "位置和占画面比例",
  "pose": "姿态与状态",
  "note": "为什么这么选、哪里最容易出戏",
  "prompt": "最终生图指令"
}
```

「重新合成」时，用户输入的想法会以
`用户本人对这次合成的具体要求（优先级最高，必须满足）：…`
的形式追加到三个阶段指令末尾。

## 阶段 ④：火山方舟生图

```http
POST https://ark.cn-beijing.volces.com/api/v3/images/generations
{
  "model": "doubao-seedream-5-0-flash",
  "prompt": "<阶段 ③ 的 prompt>",
  "image": ["<场景图 base64>", "<参考人物 base64>"],
  "size": "1728x2304",
  "response_format": "url",
  "watermark": false
}
```

- 比例映射：3:4 → `1728x2304`，4:3 → `2304x1728`，9:16 → `1440x2560`，16:9 → `2560x1440`
- `size` 被模型拒绝（400 且提到 size）时自动改用 `"2K"` 重试
- 出图后本地再按目标比例裁切一次
- 超时：客户端读超时 10 分钟（5.0 pro 较慢）
- **Seedream 接口没有 `negative_prompt` 字段**，负向约束必须写进正向提示词

---

## 错误处理

| 情况 | 行为 |
|---|---|
| 429 限流 | 退避重试：5s / 20s / 60s / 60s，遵守 `Retry-After`（上限 120s） |
| 429 额度类（quota / arrears / 额度） | 不重试，直接失败并提示 |
| 正文为空（思考吃满 token 等） | 用最小请求形状重试一次 |
| 思考参数被拒（400/422） | 退回不带 `thinking` 的最小请求 |
| 单张失败 | 标记失败，队列继续处理下一张，可单张重试 |
| worker 异常 | 记录后继续运行；若处理完仍为「排队中」则标记失败，避免无限排队 |
